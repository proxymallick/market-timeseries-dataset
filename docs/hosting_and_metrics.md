## Suggested division of roles

Use Hugging Face Datasets for a useful, versioned dataset distribution and Zenodo for a citable release with a DOI and preserved versions. Keep source code and small manifests in GitHub. Do not put the roughly 235 GB local collection into GitHub: GitHub recommends keeping a repository's on-disk Git size under 10 GB, and each GitHub release asset must be under 2 GiB (though the total release size has no cap). Hugging Face documents a 200 GB recommended per-file size, a hard 500 GB per-file maximum, no fixed repository-size cap for datasets, and account-level storage quotas. Zenodo's current API documentation describes a 50 GB total limit per record/file and up to 100 files per record. Therefore, a 235 GB dataset needs deliberate sharding and a confirmed storage plan; it does not fit as one Zenodo record or one Hugging Face file. Confirm available account quota and any current policy before upload.

Hugging Face's public dataset API exposes downloads for the last 30 days. Its organization-level daily analytics export is a separate plan feature. GitHub exposes public release-asset download counts and stars without authentication; GitHub's repository traffic views and clones endpoints require repository access and require the optional authenticated collection mode. Zenodo views/downloads are read from the public record response `/api/records/{id}`. Zenodo defines `views` and `downloads` for the specific record ID (`recid`), while `version_views` and `version_downloads` aggregate the entire concept (`conceptrecid`) across all versions. The collector labels the latter as `all_version_views` and `all_version_downloads`; it also stores each version record’s own `views` and `downloads` from the `links.versions` endpoint. A sample public response was checked directly on 2026-10-09. Kaggle's public metadata may omit view/download fields, which are recorded as blank with `unavailable` status rather than as zero. Confirm endpoints and field availability against the selected account and record before depending on them.

## Local collection

Run `python3 scripts/collect_metrics.py`. The collector uses only Python's standard library and makes read-only requests to public APIs. Configure public IDs in `hosting/metrics_config.json`. It appends/upserts `metrics/metrics_log.csv` using the columns `collected_at_utc,host,resource_id,metric,value,window_start,window_end,status`. GitHub views and clones are kept as per-day observations for the available 14-day API window; repeat collection revises the same daily bucket rather than adding the rolling total again. Hugging Face's last-30-day count is stored as a rolling-window observation. Stars, release-asset counts, Zenodo counters, and Kaggle counters are daily cumulative snapshots; values are never summed across snapshots. A failed configured endpoint adds an `unavailable` status row and makes the command return nonzero. Error bodies and response contents are never written to the log. An unconfigured host is skipped and does not generate fabricated zeroes.

For the private repository, run `python3 scripts/collect_metrics.py --github-auth` with an already authenticated GitHub CLI, then `python3 scripts/render_analytics.py`. The collector invokes the CLI without inspecting stored credential values. The weekly workflow uses its repository token or an optional `REPO_ANALYTICS_TOKEN` secret and commits only the CSV and rendered summary. The current account plan blocks private Traffic Insights; missing API authorization also makes counters unavailable. See [analytics access notes](github_analytics.md).

`hosting/downloads_badge.json` is a Shields endpoint JSON placeholder that explicitly says `not published`. It contains no invented count. Replace the message only after a real public dataset and a defensible count source exist.

## Current official references (checked 2026-10-09)

- [GitHub repository limits](https://docs.github.com/en/repositories/creating-and-managing-repositories/repository-limits) — recommended repository on-disk size and general repository guidance.
- [GitHub release storage and bandwidth quotas](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases) — per-asset and total release limits; release assets expose download counts.
- [GitHub REST API: repository traffic](https://docs.github.com/en/rest/metrics/traffic) — views and clones are per-day data; availability requires repository access.
- [Hugging Face Hub storage limits](https://huggingface.co/docs/hub/storage-limits) — account quotas and per-repository/file recommendations and limits.
- [Hugging Face dataset API client reference](https://huggingface.co/docs/huggingface_hub/en/package_reference/hf_api) — dataset `downloads` is the prior 30 days.
- [Hugging Face Publisher Analytics](https://huggingface.co/docs/hub/publisher-analytics) — daily breakdown is an organization analytics feature.
- [Zenodo API](https://developers.zenodo.org/) — documents `GET /api/records/:id`; the [statistics implementation](https://github.com/zenodo/zenodo/blob/master/zenodo/modules/stats/utils.py#L655-L719) scopes unprefixed counters to `recid` and `version_*` counters to `conceptrecid`. This distinction matches the [statistics FAQ](https://zenodo.org/help/statistics), which describes aggregate and per-version counts. A [sample public record response](https://zenodo.org/api/records/5109709) inspected on 2026-10-09 contained the corresponding fields. [Zenodo quota guide](https://help.zenodo.org/docs/deposit/manage-quota/) documents default quota details.
- [Kaggle API documentation](https://www.kaggle.com/docs/api) — dataset API access and authentication requirements may vary; this collector does not read Kaggle credentials.
